# 無限城 · 鬼滅之刃同人動作演示

以 three.js 製作的第三人稱動作遊戲演示：無限城場景、三波鬼群、上弦之參・猗窩座首領戰，以及上弦之壹・黑死牟首領戰（還原漫畫的兩段狀態）。可選竈門炭治郎、富岡義勇、炎柱煉獄杏壽郎、蛇柱伊黑小芭內、風柱不死川實彌或岩柱悲鳴嶼行冥。非營利同人作品，僅供個人測試。

線上版：<https://infinity-castle.informaltech.workers.dev>（Cloudflare Workers 靜態託管）

## 執行

```bash
pnpm install
pnpm dev        # http://localhost:5190
```

重新部署（設定見 `wrangler.jsonc`）：

```bash
pnpm build && wrangler deploy
```

除錯捷徑：`/?play=tanjiro&mode=story`、`/?play=giyu&mode=boss`、`/?play=obanai&mode=kokushibo`（亦可 `rengoku`、`sanemi`、`gyomei`）直接開打，略過選單；加 `&diff=duel`（或 `easy`、`hard`）只在這次試玩該難度，不改存檔設定；黑死牟另可加 `&seed=數字` 固定出招與月牙，`&tier=coop` 單人試打多人強度。主控台可用 `__game.runBot(3600)` 以自動操作跑完整場戰鬥並回報錯誤；`src/game/bot.js` 的 `ReaderBot` 是會看預兆、格擋閃避、只在破綻出手的測試用對手，用來調真劍的平衡。

測試頁：`/tests/pose.html`（動作實驗室）、`/tests/textures.html`、`/tests/ui.html`、`/tests/audio.html`。

手機檢查（需先 `pnpm dev`；以無頭 Chrome 模擬手機，觸控經 DevTools 協定送出真實多點觸控）：

```bash
node tests/mobile.mjs touch ip14    # 搖桿、視角、各按鈕、鎖定、暫停、模式切換、自動解析度、影格上限等 23 項檢查
node tests/mobile.mjs shots se      # 各畫面截圖 → tests/out/mobile/（`shots desk moon`：黑死牟的選角與戰鬥畫面）
node tests/mobile.mjs bars          # iPhone Safari：向上滑動收起網址列的提示（顯示、收起、戰鬥中暫停、略過）
```

裝置代號：`se`（667×375）、`ip14`（844×390）、`safari14`（含工具列）、`pixel`、`small`（640×320）、`ipad`、`desk`、`portrait`。

以最後使用的輸入自動切換：手指觸碰畫面即顯示觸控按鈕，按任意鍵、移動滑鼠或使用手把即切回鍵鼠介面；切回觸控的那一下觸碰本身就會操作搖桿或按鈕（`?touch=1`／`?touch=0` 可強制指定，便於在電腦上測試）。其他手機專屬處理：

- **版面**：觸控螢幕且畫面高度 540 像素以下時改用精簡版面，所有選單在 320–430 像素高的橫向手機上皆可完整顯示；角色說明與操作說明改為可捲動；選單邊緣避開瀏海，點擊範圍加大。電腦上的矮視窗維持原本版面。直向持機時顯示「請將裝置轉為橫向」；手機關閉自動旋轉時，Android 可輕觸該提示改用全螢幕橫向。
- **全螢幕**：在標題畫面輕觸時，Android Chrome 與 iPad 會進入全螢幕並鎖定橫向。iPhone Safari 不支援網頁全螢幕：網址列與分頁列露出時會提示向上滑動，一滑即可收起（頁面本身可以捲動，遊戲層固定不動，`src/ui/safari-bars.js`）；若要完全沒有瀏覽器介面，可從分享選單「加入主畫面」，之後由主畫面圖示開啟（`public/manifest.webmanifest`）。
- **效能**：觸控裝置預設「自動」解析度，只在戰鬥進行中依實際影格率逐步調整像素比（0.6 至 2 倍），略過開局暖機與載入卡頓；高更新率螢幕略過整數次更新，約每秒 60 格繪製（120／144／165 Hz 分別每 2／2／3 次更新繪製一次）以省電降溫。
- **其他**：切換應用程式或鎖定螢幕時自動暫停並靜音（在首領登場等過場中暫停時，配樂與畫面一起停住）；攔截雙指縮放、雙擊放大與下拉重新整理；按鈕避開瀏海與主畫面指示條（safe area）。iPhone 側邊靜音開關開啟時不會有聲音。
- 設定中可調整觸控按鈕大小（小／中／大），「滑鼠靈敏度」在觸控模式下即為視角靈敏度。

## 首領

- **上弦之參・猗窩座**：破壞殺。血量六成時展開術式「羅針」，兩成五時進入終式・青銀亂殘光。
- **上弦之壹・黑死牟**（選單「直接挑戰・黑死牟」）：月之呼吸，每一刀都帶出大小不一、短暫殘留的月牙。
  - 第一形態：原本的刀，壹之型・闇月・宵之宮（居合）、貳之型・珠華之弄月、參之型・厭忌月・銷蝕、伍之型・月魄災渦（不揮刀，月牙在身邊迴旋）、陸之型・常夜孤月・無間。
  - 血量一半時「刀身變化」：虛哭神去伸長、分岔，刀身睜開眼睛，攻擊範圍約翻倍，改用漆之型・厄鏡・月映、捌之型・月龍輪尾、玖之型・墮月・連面、拾之型・穿面斬・籮月、拾肆之型・兇變・天滿纖月、拾陸之型・月虹・孤留月。
  - 通透世界：連續猛攻會被看穿，閃身後以居合反擊。
  - 落敗：斬首後長出新頭、全身冒出刀刃，看見自己的倒影後崩解，只留下一支笛子。
  - 強度分單人與多人兩檔（`src/actors/kokushibo.js` 的 `KOKUSHIBO_TIERS`）。多人檔血量隨人數加成，傷害、速度、月牙密度更高，拾陸之型同時落向所有玩家。首領的出手對象由仇恨決定，出招與月牙全部來自同一個隨機種子，為之後的連線合作預留。

## 難度與真劍

設定的「難度」有簡單、普通、困難、真劍四檔。前三檔調整傷害與首領預兆的長短；首領每一擊出手前都會停在蓄勢的姿勢，並在命中前約三分之一秒讓刀尖或拳頭亮起（`src/game/rules.js`、`ActionRunner` 的蓄勢停頓）。

以下改動適用於所有難度：

- 無法格擋的招式頭上浮現紅色「危」字；首領血條下方顯示架勢條。
- 猗窩座的跳躍招式落在起跳時標定的位置，不再空中追蹤；相應地，連招後的收招空檔略為縮短。
- 空中拳與衝擊波無法格擋；被格擋的地裂不再放出衝擊波。
- 首領破勢期間不會轉換階段，破勢結束後才轉換。

**真劍**是另一套規則，目標是招來招往的對決：

- **讀首領**：每一擊都有預兆，但首領會延遲出招（出招節奏由他觀察你閃避的早晚而定）；無法格擋的招式頭上浮現紅色「危」字。連招有兩到四擊，收招後有明確的破綻；黑死牟收刀時會甩刀（血振）。
- **首領讀你**：連續出手太多下會被看穿反擊；在他空閒時放呼吸法，會被閃開並回敬；常舉刀防禦，他改用破防與無法格擋的招式；保持距離，他多用突進與遠距離招。
- **架勢**：首領不會被普通攻擊打出硬直。格擋與完美閃避削減他的架勢（首領血條下方的架勢條），反擊暴擊削得更多；架勢崩潰即「破勢」，靠近可「處決」，一刀奪走百分之八的血量。只有連招最後一擊被格擋時他才會被彈開。
- **玩家**：攻擊與呼吸法消耗耐力；呼吸幾乎不自然回復，靠格擋與完美閃避累積；呼吸法沒有無敵時間，也不能一招接一招；格擋的判定只在剛按下的瞬間，連按會縮短；受傷後血條上的金色部分可在短時間內以反擊奪回。
- **新招式**：猗窩座的腳式・流閃群光（三連踢）、腳式・飛遊星千輪（空翻踵落，無法格擋）、破壞殺・鬼芯八重芯（八連拳，專破防禦）；黑死牟的直刺（無法格擋）、側步閃身。
- **平衡（自動測試）**：會看預兆的測試對手對猗窩座約勝五成半、對黑死牟約勝三成半；只會亂按的對手幾乎全敗。

## 技術要點

- **手繪畫風**：自寫卡通著色（兩階明暗、筆觸式明暗交界、邊緣光），後製以深度＋法線偵測描出墨線並逐格抖動，再疊和紙紋理、分色調色與泛光。
- **動畫感**：角色由基本幾何體組成的骨架驅動；劍招以「揮劍平面」參數描述再用 IK 解出手臂，動作以 15 fps 逐格顯示（可在設定改為流暢），劍光軌跡則以連續姿勢取樣，呈現動畫式的殘影弧線。
- **鎖鏈鐵球**：悲鳴嶼的手斧握在右手（沿用揮劍平面），鐵球平時以擺錘物理垂掛左手；招式以身體座標的關鍵點描述鐵球與手斧的飛行路線，依招式本身的時鐘前進（停頓、命中停頓都跟著停），招式被打斷時鐵球帶著速度甩回、手斧飛回手中。鎖鏈每格沿「鐵球→左手→右手→手斧」的曲線重新排列鏈環（`src/actors/flail.js`）。
- **打擊感**：個別角色的命中停頓、鏡頭震動、白閃、斬擊線、火花與水花、衝擊幀（黑白反相）、集中線、徑向模糊、慢動作。
- **聲音與配樂**：音效全部以 Web Audio 即時合成。主畫面、猗窩座出場與首領戰使用錄音（`public/music/`），其餘配樂即時合成（黑死牟戰為琵琶與笛的合成曲，刀身變化後轉為更激烈的段落）；錄音載入失敗時自動改用合成配樂。
- **錄音循環**：原曲並非為循環而寫，循環點經離線分析取在同一樂段、和聲與節拍相位一致的兩個小節之間（戰鬥曲 132 BPM、每輪 48 小節；主畫面曲 128 BPM、每輪 72 小節），再以等功率交叉淡化銜接。出場曲的第二記重擊對齊首領字卡，轉強處對齊交還操控的瞬間，播畢自動交接戰鬥曲；進入第二階段時戰鬥曲不中斷。
- **貼圖**：全部以 Canvas 程序化繪製。

## 預告片

`trailer/` 以遊戲本身逐格渲染預告片，目前有兩支：

| 時間軸 | 長度 | 內容 | 配樂 |
|---|---|---|---|
| `main`（預設） | 約 80 秒 | 竈門炭治郎、富岡義勇對上弦之參 | 錄音（戰鬥曲、出場曲） |
| `moon` | 約 99 秒 | 風柱、岩柱對上弦之壹，以及真劍難度 | 遊戲內即時合成的黑死牟戰曲，離線渲染；刀身變化時轉入第二段 |

無頭 Chrome（使用顯示卡）載入 `/trailer/`，虛擬時鐘讓遊戲、介面動畫與計時器都只在擷取時前進一格，每格截圖（含 HUD 與字卡）直接送進 ffmpeg；音效在擷取時只記錄，事後以原本的音效引擎離線重播，與畫面同步到毫秒，再和配樂混音、響度正規化後封裝。正式擷取前會先把整段無聲預跑一遍：網頁字型的子集第一次畫出時需要一點真實時間，擷取的速度遠快於真實時間，不預跑的話，字卡與介面文字的頭幾格會是空白。

```bash
pnpm dev                                        # 另開一個終端機
node trailer/capture.mjs --scale 2              # 第一支：1080p60，兩倍解析度超取樣 → trailer/out/trailer.mp4
node trailer/capture.mjs --tl moon --scale 2    # 第二支 → trailer/out/moon.mp4
node trailer/capture.mjs --tl moon --preview    # 540p30 草稿（模擬結果相同）
node trailer/capture.mjs --from 41 --to 56      # 只渲染一段
node trailer/capture.mjs --sheet 0.5            # 縮圖總覽
```

鏡頭、字卡、配樂剪接與音效提示在 `trailer/shots.js`（第一支，對齊戰鬥曲 132 BPM 的小節線）與 `trailer/moon.js`（第二支，對齊黑死牟戰曲 120 BPM，每小節 2 秒）；每個場景自行重建舞台並重設亂數種子，任何片段單獨渲染結果都與整段相同。`/trailer/?tl=survey` 是逐招巡覽（含黑死牟各型、真劍的格擋與處決），用來挑鏡頭。

## 目錄

- `src/render/` 渲染管線、卡通材質、程序化貼圖
- `src/actors/` 骨架、動畫、角色模型、玩家／小鬼 AI；`boss.js` 首領共用底層與猗窩座，`kokushibo.js` 黑死牟，`flail.js` 悲鳴嶼的鎖鏈鐵球
- `src/game/` 遊戲流程、戰鬥判定、招式資料、鏡頭、HUD 橋接；`rules.js` 各難度規則（真劍）
- `src/fx/` 粒子、劍光、斬擊弧、水龍／火龍／白蛇／旋風／岩塵、衝擊波、月牙（`crescents.js`）、畫面特效
- `src/world/` 無限城場景生成
- `src/ui/` 選單與 HUD（`touch.js` 觸控按鈕、`compact.css` 手機精簡版面）；`src/core/device.js` 觸控偵測與輸入模式切換；`src/audio/` 音效與配樂（`music/files.js` 為錄音播放）
- `public/music/` 主畫面、出場與首領戰錄音
- `tests/` 動作實驗室（`pose.html`）、貼圖、介面、音效測試頁
- `trailer/` 預告片：虛擬時鐘、兩支預告片的場景腳本、字卡、音效記錄與離線混音、擷取程式
